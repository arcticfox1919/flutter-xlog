# XLog 示例与性能测试

[English](README.md) | 简体中文

默认实例 `xlog_example` 和业务子实例 `xlog_other` 在 Android / iOS 启动入口创建，
Dart 只绑定已有实例。页面分别提供写入示例、1,000 条和 10,000 条测试按钮；
业务子实例还支持刷写并查看今日文件路径。

两个实例均使用 INFO、异步模式、关闭控制台、8 MiB 文件分割阈值和 7 天保留期。
**默认实例、子实例之间必须使用独立的日志目录和缓存目录。** 原生清理扫描整个目录，
不同前缀不能隔离清理策略。示例使用同一父目录下的独立子目录。

## 运行

在 Android 或 iOS 真机运行，性能比较建议使用 `flutter run --profile` 或
`flutter run --release`。Debug 和模拟器适合验证功能，不能代表真机发布性能。

示例在 Android 和 iOS 均依赖原生 xlog 1.4.0，需使用包含当前配置字段和 writer C API
的匹配原生包。iOS 需在 macOS 执行 `pod update mars-xlog xlog` 更新锁文件后构建。

## 测量口径

- 每条正文固定为 **256 字节 UTF-8**，含请求编号、路由、耗时、trace 和中文说明，
  不含 tag、原生时间戳和日志头；压缩后的文件大小不等于正文大小。
- 每轮先生成消息并预热 200 条，再刷写，然后测量 1,000 / 10,000 条提交。
  消息生成、预热、isolate 启动和刷写不计入提交耗时。
- 提交耗时包含真实公开 writer 的编码、FFI 和原生提交成本，另列平均每条耗时与吞吐量。
  单独测量最后一次同步刷写，包含平台通道和原生刷写开销。
- 工作 isolate 独立绑定 writer，页面串行运行测试，避免多个按钮同时写入干扰结果。
  writer 返回失败或 INFO 被过滤时，显示错误而不生成成功结果。
- 异步提交成功不代表持久化完成；同步刷写也不承诺断电持久化。
  测试比较的是同一模式下的应用调用成本，不是纯磁盘带宽或最大持久化吞吐量。
- 每轮实际额外产生 200 条预热日志。测试会累积日志，持续多轮可能触发文件分割；
  同机同模式重复测量，保留波动。页面保存最近 8 次结果，可复制为表格文本。

## 验证

在 `example` 目录执行 `flutter analyze` 和 `flutter test`。测试覆盖消息字节数、
预热与刷写顺序、提交失败、两个实例四组按钮、运行互斥、错误反馈和子实例文件演示。
本机测试使用可替换客户端，不会把模拟数据作为设备性能结果。

原生依赖准备好后，可在设备运行 `flutter test integration_test/benchmark_test.dart -d <设备ID>`，
验证真实 FFI 写入、工作 isolate 刷写与子实例文件查询。
